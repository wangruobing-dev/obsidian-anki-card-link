# 有道云笔记发布指南

## 1. 功能说明

**同步当前笔记到有道云** 会把当前 Markdown 笔记发布为一份单向的有道云笔记副本。

- 首次同步会在有道云笔记的“我的文件夹”下创建 `Obsidian` 文件夹。
- Vault 中的目录会在 `Obsidian` 下逐级镜像。例如 `Java/Spring/IOC.md` 会放到 `Obsidian/Java/Spring/IOC.md`。
- Vault 根目录的笔记会直接放到 `Obsidian` 文件夹内。
- 后续同步会更新已绑定的云端笔记；本地笔记改名或移动时，会保留 binding 并移动或改名同一份云端笔记。
- 删除本地笔记只会清理本地 binding，绝不会删除云端笔记。

这是单向发布副本。你在有道云笔记中手动修改的内容，会在下一次从 Obsidian 同步时被覆盖。

## 2. 连接有道账号

打开 **设置 → Anki Card Link → 有道云笔记**。

### 推荐：官方登录窗口

1. 点击 **连接账号** 或 **重新连接**。
2. 在弹出的有道官方页面完成登录。
3. 回到小型连接窗口，点击 **完成连接**。
4. 点击 **测试连接**。

插件只把有道请求所需的浏览器凭据保存到自己的 `data.json`。不要分享该文件。

### 备用：粘贴网页 Cookie Header

如果登录窗口无法完成，在 **手动连接（备用）** 中粘贴从有道网页复制的完整 `Cookie:` 请求 Header。若你单独拿到了 `YNOTE-PC`，也可以直接粘贴它的值。

- 请粘贴完整 Header，不要随意只复制某一个 Cookie 值。
- 浏览器复制出的 Header 可能没有 HttpOnly 的 `YNOTE-PC`，这是正常现象；只要 `YNOTE_SESS` 会话有效，插件可以直接使用。
- 不要把 Cookie 写进笔记、Issue、截图、聊天记录或 Git 提交。
- 页面中的 API Key 输入框是兼容旧配置保留的；当前网页同步不需要、也不会发送该值。

## 3. 先测试，再发布

连接后点击 **测试有道连接**。

该测试只读取账号根目录，不会创建 `Obsidian` 文件夹、笔记、图片或公开链接。因此测试成功表示认证与读取权限正常；首次真实同步仍会继续验证创建、上传和公开分享权限。

## 4. 同步一篇笔记

1. 在 Obsidian 中打开一个 Markdown 笔记。
2. 打开命令面板，运行 **同步当前笔记到有道云**；也可以在文件右键菜单中执行同名命令。
3. 首次同步后，在有道云笔记中打开 **我的文件夹 → Obsidian**，确认笔记已出现。
4. 插件会创建公开分享链接、尽量自动复制，并把链接写入源笔记的 `youdao` 属性。

有道可能为新建 Markdown 笔记显示自动生成的标题。找不到时，请先进入 `Obsidian` 文件夹，再按修改时间或源笔记里的 `youdao` 链接确认，不要只按原文件名查找。

## 5. 内容与图片规则

- 成功同步后，除写入 `youdao` Frontmatter 属性外，不会改动源 Markdown。
- 本地图片附件会上传并在云端笔记中引用。
- 插件按 Vault 相对路径追踪云端笔记，不会只因标题相同就覆盖无 binding 的陌生云端笔记。
- 云端笔记被删除后，下一次同步会新建一篇笔记，并生成新的分享链接。

## 6. Cookie 过期与重新连接

有道没有向本插件提供固定、可靠的网页 Cookie 有效时长。退出登录、修改凭据、清理浏览器会话、风控或服务端策略变化都可能让会话提前失效。

插件不会设置后台自动续期定时任务。没有持久凭据时，定时请求无法安全续期复制来的浏览器会话，反而会制造无意义失败。

测试或同步提示认证失败时：

1. 点击 **重新连接** 后再次登录，或重新获取完整网页 Cookie Header。
2. 使用手动方式时，用新值覆盖旧 Cookie。
3. 再次点击 **测试有道连接**。
4. 测试通过后再重试同步。

单纯更换过期 Cookie 不需要重建云端根目录，也不需要重新配置既有 binding。

## 7. 常见问题

| 现象 | 原因 | 处理方法 |
| --- | --- | --- |
| `A Youdao browser Cookie or YNOTE-PC is required` | 没有保存可用凭据。 | 连接账号或粘贴完整 Cookie Header。 |
| 认证失败 | 保存的网页会话缺失或过期。 | 重新连接或重新复制完整 Cookie，然后测试。 |
| 测试成功但首次同步失败 | 测试只读；创建、图片上传或公开分享在真实同步时才会执行。 | 查看具体报错，确认网页端可创建并公开分享笔记；必要时重新连接后再试。 |
| 新笔记分享时出现 `VERSION_CONFLICT` | 旧版客户端在首次公开分享时错误提交了版本号。 | 升级到 1.6.2 或更高版本后重试；修复版不会提交该字段。 |
| 在有道中找不到同步笔记 | 有道可能显示自动生成的 Markdown 标题。 | 进入 **我的文件夹 → Obsidian**，按源笔记 `youdao` 属性或修改时间查找。 |

## 8. 隐私与范围

- Cookie 凭据与分享链接都属于敏感信息，请妥善保管 `data.json`。
- 公开分享链接可能被任何获得该链接的人查看，分享前请确认有道的权限设置。
- 此功能已在桌面端验证；移动端手动 Cookie 配置尚未进行真机验证。
